Panora 6.15 — восстановление подтверждения заказа при конфликте номера

Исправлено:
- клиентское подтверждение заказа больше не падает сразу при ошибке Supabase orders_order_number_key;
- после сетевой/серверной ошибки Panora сначала проверяет заказ по UUID, чтобы не создавать дубль при неопределённом ответе;
- при конфликте order_number выполняются до 3 безопасных повторов с тем же UUID заказа;
- если нумерация базы всё ещё рассинхронизирована, корзина не очищается и пользователь получает понятное сообщение без потери заказа;
- добавлен отдельный SQL repair SUPABASE_PANORA_6_15_ORDER_NUMBER_REPAIR.sql: синхронизирует sequence с MAX(order_number) и устанавливает защитный BEFORE INSERT trigger от повторного номера;
- старый workflow закупки не возвращался, логика фактической выпечки/склада/финансов не менялась.

Важно:
1. Выполнить SUPABASE_PANORA_6_15_ORDER_NUMBER_REPAIR.sql в Supabase SQL Editor один раз.
2. Затем обновить приложение до 6.15.
3. Повторить подтверждение заказа — сохранённая корзина должна остаться доступной до успешного ответа Supabase.

PWA/cache build: 6150.
