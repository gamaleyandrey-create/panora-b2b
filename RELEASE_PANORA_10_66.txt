Panora 10.66 — Производство, партии, прослеживаемость и санитарный контроль
build 10660 / cache 10660

Основа: Panora 10.65 (build/cache 10650). Изменения выполнены поверх 10.65 без отката.

Что добавлено
- Новая группа Пекарни «Производство и безопасность»: Производство, Партии хлеба, Сырьё и партии, Аллергены, Санитарный контроль, Документы, Прослеживаемость.
- Производственный журнал с планом/фактом, браком, ответственным, статусами и историей изменений.
- Автоматическое создание человекочитаемых LOT после подтверждённой фактической выпечки.
- Партии хлеба как слой прослеживаемости поверх существующего физического склада; второй склад хлеба не создаётся.
- FIFO-распределение по разрешённым партиям, ручная корректировка привязки и блокировка партии без автоматической отмены заказов/финансовых документов.
- Связь B2B-отгрузок и Retail-движений с партиями хлеба.
- Партии сырья: поставщик, приход, партия поставщика, срок годности, документ и комментарий; FIFO-подбор партий сырья для производства с ручной заменой.
- Расширенная техническая информация хлеба поверх существующих карточек/рецептур.
- Структурированные 14 аллергенов ЕС у ингредиентов; автоматический расчёт аллергенов хлеба, отдельные «Содержит» и «Может содержать следы».
- Клиентская безопасная версия состава без граммовок, закупочных цен, себестоимости и технологических данных.
- Экран прослеживаемости назад: LOT хлеба → производство → рецепт → ингредиенты → партии сырья → поставщики.
- Экран прослеживаемости вперёд: LOT хлеба → B2B → ресторан → DN/Albarán и LOT → Retail.
- Санитарные журналы: уборка, температуры, вредители, оборудование, инциденты.
- Реестр документов с категориями и контролем срока действия.
- Компактный контроль «Сегодня» и уведомления только по важным отклонениям.
- Offline-очередь новых производственных/санитарных данных с однократной отправкой после восстановления связи; без постоянного polling.
- Используется существующий Audit Trail Panora для важных изменений.

Интеграция
- Существующие Partner, Finance, Delivery, DN и Retail checkout не переписаны.
- Текущий общий физический склад хлеба и существующая схема резервов B2B/Retail остаются источником количества.
- Заблокированные LOT исключаются из новых автоматических B2B/Retail распределений.
- Клиентские интерфейсы получают только разрешённую информацию о составе/аллергенах/хранении.

Supabase
- Добавлена обратно совместимая миграция PANORA_10.66_PRODUCTION_SAFETY.sql.
- Миграция создаёт production_safety_state для синхронизации производственного контура и product_customer_safety для безопасных клиентских данных.
- Миграция не удаляет и не изменяет существующие данные.
- Для межустройственной cloud-синхронизации нового контура миграцию необходимо применить в Supabase. До этого локальная/offline работа остаётся доступной.

Проверки перед выпуском

- inline scripts HTML;
- HTML и локальные пути ресурсов;
- service worker и cache 10660;
- build/version 10.66 / 10660;
- тесты новой логики партий и прослеживаемости;
- отсутствие 15-секундного polling;
- целостность FULL и двух GitHub-частей.
