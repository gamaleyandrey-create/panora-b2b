Panora 10.67 — гибкое планирование дня выпечки
build 10670 / cache 10670

Основа: Panora 10.66 (build/cache 10660). Изменения выполнены поверх 10.66 без отката.

Что изменено
- Календарь выпечки больше не требует заранее вводить количество каждого хлеба.
- Для дня выпечки сначала отмечаются виды хлеба, которые планируются к выпечке.
- Для выбранного хлеба поле «План, шт.» стало необязательным: пустое значение означает, что рабочее количество определяется текущими заказами.
- В диалоге дня выпечки показывается фактическое текущее «Заказано»; оно обновляется автоматически и не перезаписывает ручной план.
- Если по хлебу уже есть активные заказы, хлеб остаётся выбранным, но ручной план можно менять.
- Рабочее количество к выпечке рассчитывается как max(ручной план, текущий спрос B2B + Retail).
- Закупка сырья использует тот же принцип: реальные заказы являются минимумом, а ручной план может увеличить производство для свободного остатка.
- При автоматическом восстановлении плана из заказа Panora больше не записывает заказанное количество как ручной план.
- Наличие хлеба в B2B-календаре определяется самим фактом выбора хлеба на дату, а не ненулевым значением planned_quantity.
- Фактическая выпечка по умолчанию подставляет максимальное из текущего спроса и ручного плана; итог всё равно задаётся пользователем при закрытии выпечки.
- В журнале склада скрыт внутренний технический маркер [panora:b2b-shipment:...] — пользователю показывается только накладная.
- Новый редактор дня выпечки локализован RU / EN / ES.

Совместимость
- SQL-миграция для 10.67 не требуется: существующая bake_items.planned_quantity уже допускает 0.
- Существующая логика заказов, B2B, Retail, Finance, DN / Albarán и складов не менялась вне описанных связей календаря.
- Panora 10.66 production/safety контур сохранён.

Проверки
- весь внешний JavaScript: node --check;
- inline scripts;
- HTML и локальные пути ресурсов;
- service worker CORE и cache 10670;
- build.json 10.67 / 10670;
- отдельный тест v1067-bake-day-selection.test.js;
- проверка zero-plan: выбранный хлеб с planned=0 сохраняется как bake_item и остаётся доступным на выбранную дату.

Примечание по историческим тестам
Старые version-pinned тесты предыдущих релизов ожидают прежние build/version и поэтому не являются критерием текущего релиза. Тест 10.67 проходит.
